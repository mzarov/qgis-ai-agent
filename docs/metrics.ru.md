# Метрики

Плагин ничего не собирает о своих пользователях. Публичные числа есть и без
этого: plugins.qgis.org считает скачивания каждой версии, GitHub — посещения
репозитория. Ни тот, ни другой не хранят историю: страница плагина показывает
накопленные итоги, GitHub забывает посещения через 14 дней. Поэтому увидеть
динамику можно только по ежедневным снимкам.

## Ежедневный снимок

Workflow `metrics` запускается раз в день (и вручную со вкладки Actions).
`tools/collect_metrics.py` дописывает числа за день в ветку `metrics` и
переписывает её README:

- `downloads.csv` — накопленное число скачиваний каждой версии по дням;
- `traffic.csv` — просмотры и клоны репозитория по дням, рядом уникальные
  посетители;
- `daily_downloads.svg` — новые скачивания за день, разница двух снимков;
- `README.md` — итоги по версиям, последние две недели и график.

В число скачиваний версии входят обновления, поэтому первые дни после релиза
примерно показывают, сколько установок в ходу: у кого QGIS предложил
обновление и кто его принял.

## Настройки

Скачиваниям ничего не нужно. Посещениям нужен токен с правом читать
административные данные репозитория: fine-grained token для этого репозитория
с **Administration: read**, сохранённый как секрет `METRICS_TOKEN`. Без него
прогон собирает только скачивания и пишет об этом.

В ветке лежат только данные; push в неё не запускает других workflow.
