# Эвалы навыков

Бенч навыков проверяет, насколько хорошо модель работает с нашими навыками.
Грузит ли она нужные навыки по просьбе пользователя? Когда навык загружен,
вызывает ли она нужный инструмент с правильными аргументами? Бенч работает на
[promptfoo](https://www.promptfoo.dev/) с любым OpenAI-совместимым адресом.
Каждый кейс — один запрос к модели, поэтому весь бенч стоит около миллиона
токенов и занимает несколько минут.

Бенч проверяет решения модели, а не их результат в QGIS. Модель может выбрать
верный инструмент, а он всё равно упадёт, или цепочка развалится на пятом шаге.
Прогон всего агента на живом проекте — следующий этап бенча.

## Что отправляет кейс

Промпты и схемы в бенч не копируются. `evals/context.py` собирает каждый запрос
собственным кодом плагина из `core/agent/request.py`, ровно как для настоящего
хода:

- системный промпт с описаниями навыков и телом загруженного навыка;
- схемы инструментов, которые есть у модели после загрузки этого навыка;
- состояние хода с описанием проекта;
- просьба пользователя, после вызова `load_skill` для проверяемого навыка и
  чтений, перечисленных в кейсе.

Проект описан в `evals/fixture.json`: слои `districts`, `roads`, `schools`,
`stations`, `dem` и `OpenStreetMap` с полями, примерами значений и описаниями
нескольких алгоритмов Processing. Правишь `SKILL.md` или описание инструмента —
следующий прогон уже мерит правку.

## Наборы

- **routing** (`evals/routing.yaml`) — первый ход, загружен только `inspect`.
  Какие навыки модель грузит по просьбе?
- **по набору на навык** (`ai_agent/skills/<навык>/evals/cases.yaml`) — навык
  загружен, кейс проверяет следующий вызов модели.

Кейсы лежат рядом с `SKILL.md`, поэтому новый навык приносит свои кейсы в той же
папке. Сборка берёт из `skills/` только `SKILL.md` и файлы Python, так что в zip
плагина кейсы не попадают.

## Кейс

```yaml
- description: Graduated classes with a count
  vars:
    request: Colour the districts by population in 5 classes
    reads: districts
    expect:
      call: set_graduated
      args: {layer_name: districts, field: pop2020, classes: 5}
```

- `request` — что пишет пользователь, по-английски или по-русски.
- `reads` — вызовы, которые агент уже сделал, через запятую. `roads` — это
  `describe_layer`, `roads/highway` — значения этого поля, `native:buffer` —
  описание алгоритма; всё берётся из фикстуры. Чтение со своим результатом
  пишется как `{steps: [{tool, args, result}]}`. YAML-список сюда писать нельзя:
  promptfoo превращает список в `vars` в отдельный тест на каждый элемент.
- `expect` — что считается правильным. Каждый ключ описан в `evals/checks.py`:
  - `call` и `args` — инструмент и аргументы, с которыми его вызвали;
  - `loads` и `not_loads` — навыки, которые модель загрузила или не должна грузить;
  - `not` — инструменты, которые нельзя вызывать;
  - `answer` — модель ответила словами, без вызова инструмента;
  - `any_of` — любое из нескольких ожиданий.

Сравнение мягкое, как читал бы ответ человек:
- строки без учёта регистра;
- `"500"` равно `500`;
- словарь совпадает, если совпали перечисленные ключи;
- `re:` начинает регулярное выражение;
- `*` только требует, чтобы аргумент был.

## Запуск

Нужен Node — для `npx`. Плагину и его тестам ничего не нужно.

```bash
export EVAL_API_URL=https://api.deepseek.com/v1
export EVAL_MODEL=deepseek-chat
export EVAL_API_KEY=...   # для локального сервера не нужен
export EVAL_AUTH=OAuth    # только если шлюз ждёт OAuth вместо Bearer
python3 evals/run.py
```

- `--suites routing,style` — только эти наборы.
- `--repeat 3` — каждый кейс трижды, в отчёте доля успехов.
- Несколько моделей через запятую в `EVAL_MODEL` сравниваются рядом.
- `EVAL_LOCALE=ru` собирает промпт как для русского интерфейса.

Раннер пишет конфиг promptfoo на каждый набор в `build/evals/` и запускает их.
Потом печатает таблицу: решённые кейсы, токены и задержка по наборам, плюс
каждый провал и что модель сделала вместо нужного. Та же таблица сохраняется в
`build/evals/summary.md`. Посмотреть кейсы по одному — `npx promptfoo view`.
Телеметрия, проверка обновлений и публикация результатов на время прогона
выключены.

## Когда запускать

- После правки `SKILL.md`, описания инструмента или ядра промпта: набор этого
  навыка, а если менялось описание навыка — ещё и routing.
- Перед релизом: всё, с `--repeat 3` для кейсов, которые колеблются.
- С новым навыком: добавить `evals/cases.yaml` рядом с его `SKILL.md`. Покрыть
  просьбы, ради которых навык существует, ловушку, от которой предостерегают его
  правила, и одну просьбу по-русски. Добавить для него кейс в routing.

`tests/test_skill_evals.py` охраняет сам бенч:
- каждый инструмент из кейса есть в его навыке;
- каждый ожидаемый навык существует;
- запрос собирает код плагина;
- проверка читает вызовы инструментов в любом виде, в каком их отдаёт promptfoo.
