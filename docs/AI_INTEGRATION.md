# Интеграция ИИ: как устроена и через что подключаемся

## Идея

Один и тот же код плагина работает с **любым API**, который понимает формат **OpenAI Chat Completions** (или совместимый с ним). Пользователь сам указывает:

- **URL API** — куда слать запросы (твой корпоративный шлюз, OpenAI, Azure, локальный Ollama и т.д.)
- **API-ключ** — хранится в keyring (безопасно, не в конфиге)
- **Модель** — имя модели (gpt-4o, claude-3-..., внутреннее имя корпоративной модели)

Плагин не привязан к одному вендору: кто-то использует корпоративный API, кто-то — OpenAI или другой сервис.

## Почему «через один формат»

Практически все сервисы и корпоративные шлюзы умеют отдавать **OpenAI-совместимый** API:

- Тот же `POST /v1/chat/completions`
- Тело: `{ "model": "...", "messages": [...], "temperature": ... }`
- Ответ: `{ "choices": [{ "message": { "content": "..." } }] }`

Если твой корпоративный API так работает — достаточно подставить его URL и ключ. Если нет — нужен тонкий адаптер (отдельный класс под твой формат).

Никакого отдельного «AI Hub» в коде не требуется: роль хаба выполняет **настройка URL**. Один и тот же код ходит на тот адрес, который указал пользователь.

## Как это выглядит для пользователя

1. **Настройки (один раз или при смене API)**  
   Кнопка «Настройки» в доке открывает окно:
   - **URL API** — например `https://api.openai.com/v1` или `https://your-company.com/llm/v1`
   - **API-ключ** — вводится один раз, сохраняется в keyring
   - **Модель** — текстовое поле, пользователь вводит имя модели (gpt-4o-mini, gpt-4o, название корпоративной модели и т.д.)

2. **Рабочий сценарий**  
   - Пользователь вводит запрос в поле («Создай макет A4 с картой»).
   - Нажимает «Сгенерировать план».
   - Плагин отправляет запрос на выбранный URL с выбранной моделью и ключом из keyring.
   - Ответ парсится (ожидаем JSON с полем `steps` или используем `tool_calls`, если API их отдаёт).
   - В доке показывается план, кнопки «Подтвердить» / «Отмена».
   - По «Подтвердить» выполняются шаги в QGIS (пока один тип — создание макета).

3. **Кто что подставляет**  
   - Ты: в настройках указываешь URL корпоративного API, ключ, имя модели — всё бесплатно у тебя.
   - Другие пользователи: свои URL, ключ и модель (OpenAI, другое облако, свой сервер).

## Что нужно сделать в коде

| Часть | Назначение |
| ----- | ---------- |
| **Настройки** | Хранить URL, модель; ключ — только в keyring. Сохранять в конфиг QGIS (QSettings) или в отдельный конфиг-файл в профиле. |
| **LLM-клиент** | Один класс: метод `chat(messages)` → POST на `{url}/chat/completions`, заголовок `Authorization: Bearer {key}`, тело с `model`, `messages`. Возврат строки ответа или разобранного JSON. |
| **Формат ответа** | Договориться с моделью: ответ должен содержать JSON с полем `steps: [{ "tool": "create_layout", "params": { ... } }]` — либо в `message.content`, либо собираем из `tool_calls` если API их отдаёт. |
| **Оркестратор** | По кнопке «Сгенерировать»: собрать контекст (опционально), вызвать LLM-клиент, распарсить план, отдать в UI. По «Подтвердить» — выполнить шаги (пока один тип инструмента). |
| **UI** | Поле запроса, кнопка «Сгенерировать план», блок с планом, «Подтвердить» / «Отмена», кнопка «Настройки» (открывает диалог URL / ключ / модель). |

Дополнительно (по желанию):

- Если корпоративный API **не** OpenAI-совместимый — добавить в настройках выбор «Тип API» (OpenAI / Custom) и класс-адаптер под твой формат запроса/ответа.
- Кнопка «Проверить подключение» — один тестовый запрос к выбранному URL с текущим ключом и моделью.

## Резюме

- **Через какой сервис:** через любой HTTP API, который пользователь укажет в настройках (URL + ключ + модель). Стандарт — OpenAI-совместимый формат.
- **Корпоративный API:** если он совместим с OpenAI — просто подставляешь его URL и ключ. Если нет — делаем маленький адаптер под твой формат.
- **Выбор модели:** пользователь сам вводит имя модели в настройках; список моделей с API (если есть) можно добавить позже.
- **Будущие пользователи:** те же настройки, свои URL, ключ и модель — без смены кода плагина.

Если хочешь, следующим шагом можно расписать конкретные поля диалога настроек и формат хранения (QSettings ключи, keyring service name) под твой корпоративный API.
