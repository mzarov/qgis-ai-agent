# ui/ — только представление

Здесь живёт исключительно логика отрисовки. Ни обработки данных, ни вызовов LLM.

## Правила

1. **Никакой бизнес-логики.** Файлы UI только рисуют компоненты и эмитят сигналы
   PyQt (`pyqtSignal`). Решения принимает `core/`.
2. **Только обёртки QGIS.** Всегда `from qgis.PyQt.QtWidgets import ...`.
   Никогда напрямую `PyQt5` или `PyQt6` — версия Qt зависит от сборки QGIS.
3. **Без Qt Designer.** Виджеты и layout собираются программно, `.ui`-файлов нет.
4. **DockWidget.** Главный интерфейс — `QDockWidget` в `Qt.RightDockWidgetArea`.
5. **Совместимость enum.** В коде уже используется паттерн
   `getattr(getattr(Qt, "AlignmentFlag", Qt), "AlignLeft", ...)` — он нужен,
   потому что Qt5 и Qt6 держат enum'ы по-разному. Сохраняй его в новых местах.
6. **Импорты** вверху, абсолютные. Без `# -*- coding: utf-8 -*-` и без docstring
   на уровне модуля.

## Контракт с оркестратором

`core/orchestrator/contracts.py::DockWidgetContract` описывает минимальный API,
которым пользуется оркестратор. **Добавил метод в `LayoutAgentDockWidget` —
добавь его и в контракт**, иначе связь молча разъедется.

## Роли сообщений чата

`ChatMessageModel` хранит роль строкой; цвет берётся в `chat/theme.py`, форма
пузыря — в `chat/delegate.py`. Обе функции переключаются по роли, так что новая
роль требует правки в двух местах.

| Роль                | Что показывает                                  |
| ------------------- | ----------------------------------------------- |
| `user`              | реплика пользователя                            |
| `assistant`         | потоковый ответ модели                          |
| `assistant_preface` | короткое вступление модели                      |
| `tool`              | активность тула: «⏳ Смотрю слои» → «✓ …»        |
| `plan`              | батч изменений на подтверждение, «☐» → «☑»       |
| `result`            | итог прогона                                    |
| `system`            | служебные сообщения плагина                     |

## Кнопки подтверждения

`confirm_btn` и `cancel_btn` скрыты по умолчанию и показываются через
`set_confirm_visible(True)`, когда агент накопил батч write-вызовов.
Не показывай их постоянно: чтение проекта подтверждения не требует.
