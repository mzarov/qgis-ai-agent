# core/ — мозг агента

Здесь живут агентный цикл, оркестрация, транспорт до LLM и состояние.
PyQGIS-логика исполнения сюда не переезжает — она в `qgis_tools/`.

## Поток управления

```
UI сигнал → CoreOrchestrator → AgentLoop.start()
              ↓
        request.py собирает messages + схемы тулов
              ↓
        ModelTurnThread (фоновый поток, только HTTP)
              ↓  сигнал
        AgentLoop._on_turn (ГЛАВНЫЙ поток)
              ├─ нет вызовов        → финальный ответ, прогон окончен
              ├─ safety=read        → выполнить сразу, результат в транскрипт
              ├─ safety=write       → validate, затем в батч, вернуть "queued"
              └─ load_skill         → подгрузить домен, вернуть список тулов
              ↓
        _request_step() — следующий виток
```

## Правила

1. **Главный поток.** `_on_turn` и `ToolExecutor.run` обязаны выполняться в главном
   потоке — там трогают PyQGIS. В фон уходит только HTTP-вызов. Не переписывай цикл
   на `while` в фоне или на `asyncio`.
2. **Write проверяется до очереди.** `BaseTool.validate` вызывается в `_queue_write`,
   пока цикл жив. Само исполнение идёт после конца цикла, и там вернуть ошибку
   модели уже некому — поэтому всё, что можно проверить по аргументам, проверяется
   здесь.
3. **Ошибка тула не рвёт прогон.** `ToolExecutor` ловит исключение и возвращает его
   модели как результат, чтобы та исправилась сама. Пробрасывать наружу нельзя.
4. **`prompts.py` — только поведение, не зависящее от домена.** Любое правило про
   конкретный домен или конкретные тулы идёт в `skills/<домен>/SKILL.md`.
   Если тянет дописать правило в системный промпт — это сигнал, что нужен скилл.
5. **Транспорт вендор-нейтрален.** Диалектов два: `openai` (`/chat/completions`,
   Bearer) и `anthropic` (`/messages`, `x-api-key`, системный промпт вне списка
   сообщений). Выбирается по адресу, в настройках можно задать вручную. Внутри
   диалекта openai транспорт пробует нативные `tool_calls`, при отказе уходит в
   JSON-протокол и запоминает выбор в `QgsSettings` по хешу URL. Все пути
   нормализуются в `ModelTurn` — цикл не знает, какой сработал.
   SDK провайдеров не подключать: диалект — это форма HTTP, а не библиотека.
6. **`MAX_ITERATIONS`** страхует от зацикливания. Не убирай и не поднимай без причины.
7. **Оркестратор только рендерит.** Решения принимает цикл; `CoreOrchestrator`
   подписан на сигналы и рисует их в чат. Логику ветвления туда не добавлять.
8. **Диалог пишется одним вызовом.** `ConversationState.add` кладёт сообщение и в
   окно модели, и в сохраняемую сессию. Не дёргай `HistoryStore` и `Session` по
   отдельности — они разъедутся, и модель увидит не то, что показано в чате.
9. **Прерывание не блокирует главный поток.** `abort` не ждёт и не убивает поток —
   отцепляет сигналы и даёт HTTP-запросу догореть в фоне, результат отбрасывается
   по флагу `_aborted`. Жёсткий `stop` с `terminate` остаётся только на выгрузку
   плагина, когда QGIS всё равно закрывается.
10. **Импорты** — все вверху, абсолютные. Код без комментариев и docstring —
   см. корневой CLAUDE.md.

## Что где

| Файл                     | Ответственность                                    |
| ------------------------ | -------------------------------------------------- |
| `agent/loop.py`          | машина состояний прогона                           |
| `agent/turn_thread.py`   | владение фоновым потоком: запуск, отцепление, остановка |
| `agent/notices.py`       | тексты, которые цикл отдаёт наружу                  |
| `agent/request.py`       | сборка messages, схем тулов и настроек транспорта   |
| `agent/executor.py`      | исполнение вызова тула с перехватом ошибок          |
| `agent/transcript.py`    | лента прогона и рендер в messages обоих протоколов  |
| `agent/prompts.py`       | ядро системного промпта, мета-тул `load_skill`      |
| `llm/transport.py`       | выбор диалекта, feature-detect, нормализация в ModelTurn |
| `llm/dialects.py`        | определение диалекта по адресу, пути и заголовки     |
| `llm/anthropic.py`       | перевод сообщений и схем тулов в формат Anthropic    |
| `llm/client.py`          | HTTP-слой, разрешение URL/ключа/заголовков          |
| `orchestrator/`          | связь UI с циклом, контракт DockWidget              |
| `state/conversation.py`  | окно для модели и текущий диалог — одной точкой входа |
| `state/session.py`       | модель диалога: заголовок, сообщения, сериализация   |
| `state/store.py`         | диалоги на диске, отбор по открытому проекту         |
